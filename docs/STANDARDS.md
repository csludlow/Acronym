## Inspected VPAT file

- [Official International edition DOCX](https://www.itic.org/dotAsset/2434a080-87fe-4db1-815e-1e032bf7ac09.docx)
- Version: 2.5Rev; International edition; retrieved 2026-11-04.
- SHA-256: `ac3243f01f9a93b965bbba5bc30c7200b08f228441931c48ca25c5f6548a771d`.
- Inspection: extracted the introductory instructions and inspected its OOXML package; it is a document with multiple standards tables, not a flat set of fixed-position answers.
- Its instructions limit **Not Evaluated** to WCAG AAA criteria. Required explanations and scope matter; an untested item must not become an invented official conformance category. The prototype does not offer Not Evaluated as a general judgment.
- WCAG mappings do not replace every software, hardware, documentation, or support provision. The app requires a human-defined criterion inventory and coverage acknowledgment.
- We have **not** verified a populated copy for preservation of all notices, wording, mappings, and structure. Creating any DOCX is not evidence of a working VPAT-based export.

## Product policy versus template requirements

The following are **our design decisions**, not claims about mandatory HECVAT or VPAT workflow:

- Every setup field is confirmable, including an explicit Unknown value that creates a follow-up task.
- Eight original preparation questions and six original accessibility starter areas are supplied. These are neither complete nor official questionnaire/standard content.
- Named review, precise source links, human attestations, revision history, and conservative approval invalidation are application rules.
- Final generic reports require confirmed setup, resolved structured claims, approved answers, judged criteria, completed recorded tests, and a human acknowledgment of scope coverage. Failure findings do not block completion merely because they failed.
- Supports requires completed passing records and a separate human coverage judgment. This is a conservative preparation gate; it does not implement every official equivalent-facilitation or applicability exception.
- An institution’s acceptance or risk decision is outside this workflow. Progress measures are counts, not compliance ratings.

## Official adapter admission requirements

`server/adapters.ts` defines a versioned interface; its registry is empty. All official export requests return a visible unsupported-template error.

Before adding an adapter, record permission, the exact template hash/version/edition, and authorized fields. Verify scoping from that exact release. Test a filled copy against the original: sheet names and order, formula text, defined names, styles, validation, evaluation calculations, required notices, criterion wording, mappings, allowed response categories, and every non-response part. Test the workbook in a spreadsheet application, not just by checking that it is a ZIP file. Unsupported versions must fail visibly. Never offer CSV or PDF as the functioning HECVAT deliverable.

HECVAT workbook fidelity has **not been tested** because no authorized adapter is implemented. A test verifies rejection, and a separate XLSX evidence test verifies that extraction leaves its input unchanged; that is not a workbook export fidelity test.

## Document library decisions

- [docx](https://docx.js.org/) creates the original generic report with semantic headings and editable paragraphs. It is not used to rebuild official templates.
- [Mammoth](https://github.com/mwilliamson/mammoth.js) extracts raw DOCX text; HTML conversion is deliberately unused.
- [Mozilla PDF.js](https://mozilla.github.io/pdf.js/) extracts PDF text by page. Image-only content needs OCR or manual transcription.
- XLSX evidence is read as bounded OOXML using fflate and fast-xml-parser. Formula text and cached values are displayed as text; nothing is calculated or rewritten. This limited reader makes no fidelity claim for Excel export.
- Dependency ranges are declared in `package.json`; CU Launch currently uses its supported npm-install fallback without a committed lockfile. Recheck guidance, package maintenance, and template releases before adding official or hosted support.
